# Smart Farmer native application

An independent React Native application for Android, iPhone and iPad. The committed `ios/` Xcode project serves both iPhone and iPad; `android/` contains the Android Gradle project. The web application remains a separate client. This application calls the backend's `/v1` API and does not import backend or web implementation.

The Forum bottom tab provides signed-in farming discussions, topics/search,
explicit text sharing and replies, author edits/removal, private reporting and
source-farm-owner moderation. It does not attach private farm data or media, and
it does not queue or replay publication offline. Unsent composer text stays in
memory only while the form is open. See the [sharing and authority model](../../smart-farmer-backend/docs/forum.md).

## Setup and builds

Use Node 24.3 or newer on the Node 24 line. Dependencies are locked to Expo SDK 58 (`expo` 58.0.23), React Native 0.88.1 and React 19.3.0.

From this directory:

```bash
npm ci
cp .env.example .env
```

Set `EXPO_PUBLIC_API_URL` to the HTTPS origin of the intended Smart Farmer API, without a path, query or credentials. This value is public build configuration. A phone cannot use the development computer's `localhost`; use an HTTPS development endpoint reachable by the device. Development builds also allow localhost and the Android emulator host alias `http://10.0.2.2:3000`. Release JavaScript refuses an HTTP API origin. No production endpoint has been assumed or configured.

Build and start a native **development build**:

```bash
# Android: requires an installed Android SDK, compatible JDK and emulator/device.
npm run android

# iPhone/iPad: requires macOS, Xcode and an iOS simulator or provisioned device.
npm run ios

# Start Metro for an already installed development build.
npm start
```

Expo Go is deliberately unsupported for private farm data. `expo-sqlite` must be compiled with SQLCipher. At runtime the app checks `PRAGMA cipher_version` before creating a cache and refuses to open a plaintext fallback.

Validation and portable JavaScript exports:

```bash
npm run typecheck
npm test
npm run build
npm audit --omit=dev
```

`npm run build` writes separate Hermes bundles under ignored `dist/ios/` and `dist/android/`; it does **not** compile an APK, AAB or IPA. It does not regenerate native projects.

Native configuration lives in `app.json`, `locales/` and `plugins/`. After a deliberate configuration or native dependency change, regenerate and review the native diff:

```bash
npm run native:generate
```

Expo SDK 58 regeneration replaces generated native output by default. Keep durable native customizations in the config plugin. The Android debug build uses the developer's standard local debug keystore, generated by Android tooling. No keystore, production signing password, Apple development team or provisioning profile is committed. Release builds are not signed using the debug key. Configure the intended release signing identities separately before store distribution. The bundle/application identifier is `eu.onesa.smartfarmer`.

## Keyboard navigation

Account forms, the workspace and editable sheets expose a localized hide-keyboard button while the software keyboard is visible. The action removes input focus without submitting or changing a draft. It stays outside the scrollable form so multiline notes and numeric keyboards remain dismissible on small screens. Native acceptance uses this real control and then checks keyboard disappearance, exact entered text and persisted results.

## Offline behavior and data protection

- A successful authenticated download is required before offline farm context is available. Paginated reads follow cursors to retrieve the selected resource history; cached context and its last synchronization time stay visible. Sync runs on foreground connectivity changes and explicit refresh; background execution is not guaranteed.
- Each API origin and user ID has a separate SQLCipher database and random key stored with device-only SecureStore accessibility. Native storage encryption is checked before any schema is created. Android backup and public file sharing are disabled.
- SecureStore retains the current session. Cold starts and returns after at least 30 seconds in the background require the device's biometric/PIN unlock. Without an enrolled device lock, online sign-in remains available; the app does not bypass local unlock to expose offline data. Always sign out before handing a shared device to another person.
- Persistent, farm-scoped drafts, outbox rows, photos, voice notes and PDFs survive an application restart. Account switching retains encrypted drafts for the same account to recover after sign-in. It does not make them available to another account. Uninstalling the app or losing its secure-storage keys can lose unsynchronized work; synchronize before replacing a device.
- Activity and animal event retries preserve the original client UUID and validated payload. The server applies stock/cost/count effects idempotently. Conflicts retain the original draft and are not silently overwritten. Task conflicts show the current server task before a user explicitly applies a reviewed change; retaining the server version archives the local proposal.
- Field record metadata is acknowledged before dependent media can upload. A photo failure never causes accepted activity metadata to be recreated. Media uploads use stable IDs, names, bytes and MIME types, visible progress and a maximum of five automatic attempts. Explicit retry preserves identity. Files are capped at 5 MiB each and pending encrypted media at 50 MiB per account. Data-saving mode defaults to Wi-Fi for media; explicit upload allows the user's current connection.
- Membership removal or a role change on reconnect clears cached farm reads and blocks pending work for review. A 401 locks the session and retains recoverable work. Session expiry is checked while the app is open and on foreground return.
- Local sign-out removes the saved session, closes the workspace, cancels local reminders and unregisters native push where possible. The online session-revocation request sends a bodyless DELETE without declaring a JSON document, so the API can reach the revocation route. Server/session/channel revocation is best-effort while offline; account session management remains available after reconnect. Ordinary push payloads contain a localized instruction to open the inbox, never private task/camera details.
- Camera/audio modules first create app-private temporary files. After completed capture, the attachment is persisted to encrypted storage and the processed temporary file is removed. This does not assert that an interrupted in-progress recording survives process termination.
- The typed/runtime-validated outbox accepts field activities, animal events, task progress, typed project/weather/usage observations and incident creation. It refuses trade, payments, plan approvals, financial corrections, commissioning and equipment commands. These consequential workflows require explicit current online authorization.

The secure cache uses SQLCipher in a native build. The automated tests below use real ordinary SQLite to verify the persistence/synchronization logic; they are **not** evidence that SQLCipher, Keychain/Keystore, device unlock or OS permissions have been exercised on hardware.

### Real gallery invoice intake

It opens More → Finance → Accounting → Scan, selects one generated synthetic invoice through the real OS gallery, restarts/re-authenticates and checks that the local image is still uploadable. After consent, the ordinary backend worker processes the same private `MEDIA_ROOT` as the API. CI installs Tesseract with English data and Poppler. A bounded, read-only queue observer checks actual image OCR, then the UI opens the authenticated original, deliberately corrects the suggested unit price, explicitly selects zero tax, saves an unposted draft and reviews/confirms posting. Server checks require one payable/expense and balanced journal, no payment, and the same authenticated source hash before and after posting. The generated PNG enters the actual library through [Maestro 2.12.0 `addMedia`](https://github.com/mobile-dev-inc/Maestro/tree/cli-2.12.0); its iOS driver uses `simctl addmedia`, and its Android driver writes to MediaStore. Native intake converts that image to JPEG, so retained-source validation compares the downloaded JPEG with the server's content hash, not the seeded PNG hash.

The strict gallery selectors are source-supported candidates and still need a passing run on the pinned Android API 36/iOS runtime. If an OS selector differs, the journey fails and retains the real hierarchy for review. It uses no coordinate fallback or picker/OCR mock. ### Retained development-launch diagnostics

The following observer coverage was added on the development-client path before accounting integration. The integrated iOS acceptance app embeds Release JavaScript and does not request a Metro manifest at startup. Native log capture remains useful, but a Metro-triggered thread observation can therefore be inconclusive; that diagnostic is not an acceptance requirement and cannot turn a failed journey into a pass. The bounded session trace also remains available for the Release app. The current workflow gives a cold XCTest driver 240 seconds to start; application request deadlines and journey assertions are unchanged.

The optional Darwin thread observer may discard one prelaunch heartbeat whose
wall timestamp and monotonic sample disagree. It clears the old baseline and
requires a strictly newer, valid heartbeat from the same process clock before
arming. A later-delivered launch event must also timestamp strictly after the
reset heartbeat; delivery order cannot hide an overlap with the launch window.
The result records that reset and whether the baseline recovered. A second
mismatch, malformed input or any mismatch during the launch window still
refuses observation. This diagnostic does not retry app startup, change request
deadlines or turn a failed native journey into acceptance.

Metro heartbeat records also retain `sampleStartedMs`, `emissionStartedMs` and
`collectionDurationMs` on the process monotonic clock. The sample start remains
the existing `intervalEndMs`; emission start is measured after CPU, event-loop
and GC collection, immediately before formatting the log. This separates late
callback entry from elapsed time inside diagnostic collection, which can include
process descheduling. It does not measure serialization or the synchronous log
write, identify a stall cause, or change heartbeat admission. The retained PR9
run at `1048696` failed heartbeat validation before native launch; these fields provide
context for a future diagnostic run without reclassifying that original failure.

Each device launch now has its own observer, native log and stop marker. The
phone retains `ios-thread-observation.json`; the tablet writes
`ios-tablet-thread-observation.json`. The later tablet observer starts at the
current end of Metro's log, so earlier phone requests, heartbeats and stop state
cannot become tablet evidence. It still requires a newly observed valid
heartbeat before sampling, and retains the same clock, query, sample and cleanup
bounds. The observer never launches the app or repeats a manifest request.

After a timely native launch, the observer also retains at most 32 recent phase
timings and the longest duration for each fixed phase, with its own process CPU
deltas. Two numeric snapshots bracket the observed interval with aggregate
runner CPU counters, load averages and free/total memory. Their wall timestamps
show how that interval overlaps the existing ten-second launch window; they are
not per-process or instantaneous scheduler measurements. CPU names, process
lists, file contents and host identity are not recorded. Missing or reset
counters remain unavailable. A late observer still reports `helper_late`; these
details do not change the thread-reader trigger, sampling or cleanup limits.
The retained PR9 native failure had no target-thread samples, so this context
can explain where evidence was lost without assigning a CPU, I/O or scheduling
cause or claiming that startup has been repaired.

The retained actual-main [native run 42394429408](https://github.com/DruHustle/smart-farmer/actions/runs/42394429408)
at `32ffb11` passed Android and all four iPhone flows, but its iPad login failed
before authentication after the local development manifest request timed out.
The phone-only observer did not cover that tablet launch. The separate tablet
observation closes this diagnostic gap; it does not establish the timeout's
